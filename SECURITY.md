# Política de seguridad

## Versiones soportadas

Las correcciones de seguridad se aplican a la versión estable más reciente.

## Reportar una vulnerabilidad

No abras una incidencia pública si el reporte puede exponer documentos, rutas locales, datos personales o una forma de ejecutar código no confiable.

Utiliza la opción **Report a vulnerability** de la pestaña **Security** del repositorio. Incluye una descripción reproducible, el impacto, la versión afectada y una prueba mínima que no contenga información privada.

El reporte será revisado antes de publicar detalles o una corrección.

## Documentos sensibles

Nunca adjuntes contratos, firmas, identificaciones, estados financieros ni PDF de terceros a incidencias o pull requests. Crea un documento sintético que reproduzca el problema.
